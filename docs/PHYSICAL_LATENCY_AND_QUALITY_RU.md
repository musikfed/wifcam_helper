# PegineLab T23N — измерение качества изображения и настоящей задержки

## Почему FFmpeg не может доказать latency сам

`ffprobe` сообщает кодек, FPS, разрешение, наличие аудио. `wifcam_helper video` измеряет скорость декодирования и расходы запуска на CORE. Ни один из этих тестов **не измеряет** промежуток от захвата света сенсором SC2336 до отображения пикселя в Hombo3. Пинг до Wi-Fi также не равен видеозадержке.

## Физический прогон, без нарушения прошивки

1. Камера смотрит на экран ноутбука/контрольный LED, где мигает крупный квадрат или бегут миллисекунды; запись ведёт **отдельный** смартфон 120/240 fps, который одновременно видит эталон и экран Hombo3 с живым RTSP.
2. Фиксировать одну настройку при одинаковых расстоянии, яркости, освещении и Wi-Fi. Снимите день (`day`), слабый свет (`night`) и быстрые движения (`motion`).
3. Определить расстояние во времени между одним и тем же событием в реальном мире и его видеокопией на мониторе. Записать измеренную задержку в миллисекундах; серия из нескольких измерений лучше одного.
4. Качество вручную оценивается от 1 до 5 по различимости деталей, выдержке, шуму/артефактам и смазыванию. Фиксировать процент фактических пропусков/разрывов, а не придумывать его.
5. Ввести **реальные** измерения в копию `profiles/quality_evaluation_template.csv` (не коммитить частные результаты), заполнить три строки на профиль/транспорт.
6. Выполнить `python3 -m wifcam_helper quality-evaluate --csv /path/to/measurements.csv`. Алгоритм не рекомендует профиль без day+night+motion и соблюдения порогов качества/потерь.
7. Снимки экрана, аудиофайлы, ключи и пароли не сохраняются в Git и не требуются для оценки.

Пример запуска исследовательского сравнения (не glass-to-glass):
```sh
python3 -m wifcam_helper compare --rtsp-url rtsp://CAMERA_IP:554/ch0 --alt-rtsp-url rtsp://CAMERA_IP:554/ch1
```
Используйте `--alt-rtsp-url` только когда второй поток действительно существует. Для Hombo3 оптимизация обычно начинается с разрешения/FPS/битрейта и одного декодера без очередей старых кадров; *не* с удаления USB DWC2, MMC, SC2336 ISP или Raptor RAD/RAC.

## Классификатор

Опциональный YOLO использует один кадр RTSP и локальную заранее установленную модель `.pt` или `.onnx` на **CORE**. Без модели загрузка из интернета не производится. `--vision-consent` обязательно:
```sh
python3 -m wifcam_helper classification --rtsp-url rtsp://CAMERA_IP:554/ch0 --model /trusted/models/yolo11n.pt --device cpu --vision-consent
# Только если RTX 3060 доступна и CUDA установлена:
python3 -m wifcam_helper classification --rtsp-url rtsp://CAMERA_IP:554/ch0 --model /trusted/models/yolo11n.pt --device cuda:0 --vision-consent
```
Доверяйте только своим модельным весам: загрузка непроверенного PyTorch `.pt` файла потенциально небезопасна. Данные изображения сохраняются только в RAM, результаты — метки классов и уверенность. Классификация кадра не заменяет работающий голосовой диалог.

## Связь с YadroKreator

По результатам ручных прогонов инженер утверждает видеопрофиль; стенд не меняет настройки камеры сам. Фабрика импортирует только проверенный JSON-пресет `WIFICAM_WEBRTC=0|1`, и то **по отдельной галочке**. Качество/задержку надо доказывать заново на собранном SD-кандидате и сохранять baseline 0.1_test.
