# WifCam Helper — отдельная SD-прошивка «головы» T23N

Эта ветка добавляет **настоящую минимальную прошивочную надстройку**, не просто тестовую веб-страницу. YadroKreator загружает `musikfed/wifcam_helper/main` и базовый код `musikfed/wificam_T23N/mymarrchWFcam` с фиксацией обоих Git SHA. На изолированном рабочем дереве сборки он добавляет строго утверждённые файлы из `firmware/overlay/` в `rootfs/` WIFICAM, затем запускает тот же контролируемый Thingino/Buildroot SD-сборщик и проверяет отдельный SD-образ.

## На камере
- `/etc/wifcam-helper-release`: отличимый от обычной WIFICAM маркер релиза.
- `/etc/init.d/S92wifcam-helper`: запускает лишь безопасную индикацию готовности на /run, **не** открывает микрофон и не запускает непрерывную запись.
- `/usr/bin/wifcam-helper-probe`: сообщает фактическое наличие команд rad (аудиовход), rac (динамик), rvd (видео).
- `/cgi-bin/helper-capabilities`: JSON-интерфейс для Huananzhi/Hombo3 через существующий CGI/HTTP стек WIFICAM, с той же действующей политикой авторизации. Отчёт показывает доступность транспорта, **не доказывает физическую работоспособность** микрофона, усилителя или сенсора.

Непрерывная речь, классификация, CV, диалоги, память, Ollama и управление VRAM выполняются на CORE. В 64 МБ RAM камеры нельзя честно обещать локальную многомодальную LLM. Видео/аудио остаются транспортом WIFICAM; отдельную двустороннюю маршрутизацию и аппаратные тесты нужно проверить после SD-загрузки. **Не считать ассистента готовым до аппаратной проверки.**

## Владение интерфейсом и звуком Helper

Helper — **отдельная редакция прошивки**. Её полноценные исходники веб-интерфейса теперь хранятся здесь, а не только в базовом WIFICAM:

- `firmware/ui/index.html` — главная страница WifCam Helper, с общими разделами сети, видео, SD, PTZ, безопасности и собственными режимами `robot_head` / `voice_assistant`;
- `firmware/ui/styles.css`, `firmware/ui/app.js`, `firmware/ui/assets/peginelab-logo.svg` — сохранённое оформление и управление без пустой «демо-мордочки»;
- `firmware/audio/boot-jingle.json` — **оригинальная семисекундная мелодия PEGINELAB**, те же 35 событий; звук описан данными, не запускаемым скриптом.

Сборочная линия `t23n_helper_sd` в YadroKreator **перед компиляцией** переносит только фиксированный набор UI-файлов в `wificam_T23N/web/` своего изолированного job, а музыкальную партитуру обрабатывает собственным безопасным генератором и создаёт `boot-jingle.wav` и `boot-jingle.s16le` (16 kHz, mono, 16-bit, 224000 байт). Затем базовый сборщик запаковывает UI, CGI, музыку, ядро и сервисы в **новый** SD-образ.

Обычная прошивка `wificam_T23N` не перезаписывается. SSH, работающую камеру, recovery SD, конфигурацию VPN и ключи сборка не трогает. При новом тесте убедись, что открылся **Helper UI на :8090**, выполняется CGI и слышен реальный звук: наличие PCM в образе этого не гарантирует.

**Известная ошибка на T23N (9 ноября):** `WIFICAM CGI PRE-FLIGHT FAILED` при закрытом :8090. Она не связана с ядром Linux; сама версия ядра уже успешно загрузилась. Новый базовый сборочный исправляющий патч включает `wget` в BusyBox, чтобы локальный CGI-тест мог получить JSON даже при отсутствии curl, и исправляет привязку PID тестового httpd. При реальной CGI-неисправности блокировка :8090 остаётся. Требуется аппаратный контроль на новой SD после сборки.

## Проверка
1. В YadroKreator открой WifCam Helper рядом с другими прошивками.
2. «Создать прошивку» создаст **новый** изолированный job, не подменяя WIFICAM 0.1_test.
3. «Проверить» сначала валидирует SD (MBR/MSPL/uImage/ext4/SHA256), затем проверит маркер уникального Helper в корневом ext4.
4. «Скачать» перепроверит файл перед выдачей .img, без автоматической записи SD.
5. После Rufus/Etcher, проверить загрузку, SSH, RTSP, `/cgi-bin/helper-capabilities`, физический микрофон и динамик.

Инструменты диагностического стенда на CORE в Python остаются в том же Git-репозитории, но НЕ являются прошивкой и НЕ копируются в 64 MB rootfs. Firmware overlay и CODE находятся в одном исходном проекте, а готовые образы и логи — внутри отдельного цеха Helper в YadroKreator.

## Режимы работы (этап 1 — переключатель, аппаратная проверка ещё впереди)

Выбор роли сохраняется на карте в `/opt/wificam/helper-mode`, а не в временном каталоге `/run`.
Значения: `robot_head` («голова Hombo3») и `voice_assistant` («голосовой помощник»).
При первой загрузке выбирается `voice_assistant`; смена не перезапускает видеосервис и не двигает PTZ.
Загрузка и возврат к предыдущему режиму не меняют разметку SD.

На камере по SSH:
```sh
/usr/bin/wifcam-helper-mode status
/usr/bin/wifcam-helper-mode set robot_head
/usr/bin/wifcam-helper-mode set voice_assistant
/usr/bin/wifcam-helper-probe
```

Через существующий WIFICAM HTTP-сервер:
- `GET /cgi-bin/helper-capabilities` — JSON состояния (тот же HTTP Basic, что у веб-интерфейса).
- `POST /cgi-bin/helper-capabilities` — переключение с полями формы `mode=robot_head|voice_assistant` и `csrf=<токен из /cgi-bin/api?op=status>`. Требуется `REMOTE_USER` от HTTP Basic. Настроено так же, как штатные POST-операции WIFICAM; нестандартные CGI-заголовки не используются. Не передавать токен или пароль в Git.
- Проверка: при запросе с неверным токеном режим не должен изменяться. После перезагрузки значение сохраняется.

**Граница готовности:** переключение роли ещё не означает, что реализованы команды колёс, аудиостриминг, автоподключение к CORE (этап 2 добавляет реальный UI-переключатель на порт 8090). HTTP-заголовки CGI и физические устройства проверяются на реальной T23N; сборка YadroKreator сама по себе их не доказывает.

**Безопасность:** VPN — сетевой рубеж, но авторизацию HTTP и запрет произвольных команд сохраняем. Реальные пароли и ключи остаются в локальных файлах конфигурации, не публикуются в репозитории.

## Этап 2 — единый интерфейс камеры

В ветке `musikfed/wificam_T23N/mymarrchWFcam` реализована общая WIFICAM админка `http://CAMERA_IP:8090/` с отдельной автоматически обнаруживаемой вкладкой **«Голова / Помощник»**, видимой только при установленной прошивке Helper. Вкладка показывает текущий сохранённый режим, позволяет сменить его авторизованным POST с CSRF и отображает состояние команд `rad/rac/rvd`, честно маркируя аппаратную проверку как ожидающую. Остальные существующие разделы камеры (живое видео и PTZ, SD, Wi-Fi, SSH/VPN, система) сохранены. Камерный предпросмотр не включается автоматически, поток Hombo3 не прерывается. Веб-порт **8090**, не 80/443 и не 8080.
